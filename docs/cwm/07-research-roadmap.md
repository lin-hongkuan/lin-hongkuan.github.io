# 07｜从读懂论文到开始做科研

对本科生来说，不必一开始复刻 8 张 H800 的视频模型训练。更稳妥的路线是先选一个**可控、可评测、算力友好**的研究问题，做出真正可复现的闭环，再逐步扩大。

## 先把科研问题变成可验证假设

一个合格的起步问题通常能写成：

> 在 **X 条件**下，使用 **方法 M**，相对于 **基线 B**，能否让 **指标 Y** 改善？改善是否在 **场景/干预 Z** 下依然成立？

例如：

> 在长时序物体搬运任务中，使用结构化状态记忆 + 轻量可执行规则的 Agent，相比只把历史文本塞进上下文的 Agent，能否降低遮挡后对象位置错误率和无效工具调用率？

这里要分清：实验是在测试 CWM 的哪一环（状态记忆、代码执行、proxy、视频跟随），不要把多个组件同时改掉后再声称知道改进来自哪里。

## 四条本科友好的切入线

### A. 状态持久与 Agent 恢复（推荐起步）

搭一个小型 2D 网格/桌面物体世界，包含实体、位置、容器和简单规则；Agent 接收多步指令，事件被代码保存。设计遮挡、离开再返回、动作失败、规则变更等情况。

比较：仅历史对话、结构化状态、结构化状态 + 执行器/验证器。测任务成功率、状态错误率、状态恢复准确率、无效工具调用数与 token 成本。

**优点**：不用训练视频模型；很贴合 Agent 可靠性/系统研究。**边界**：这是对 CWM“可执行状态/Agent”思路的简化研究，不是完整复现原论文。

### B. Proxy 设计与条件带宽

在已有合成数据或可控环境中构建人物/物体轨迹，用框、质心、分割、深度、关键点等表示；逐步增加/删除通道与时间采样密度。

比较位置误差、实体 ID 保持、遮挡后恢复和条件成本；找“足够控制、但无需过度表达”的最小 proxy。

**关键**：先有便宜的确定性模拟/检测器基线，不要一上来就靠大视频模型做所有评估。

### C. 状态到视频条件的冲突消解

当文本说“角色停在门口”、proxy 却显示角色继续前进时，模型/控制器应该如何检测矛盾、决定重写哪个条件？可以设计矛盾类型、严重度、检测模块与拒答/修复策略。

测冲突检测准确率、误修率、最终条件服从度。这个方向与 Agent 可靠性和安全性高度相关。

### D. 长视频续窗与身份记忆

研究滑窗重叠、锚点、身份描述、外观记忆分别对跨窗身份漂移有多少影响；构建同一套固定 prompt/seed/窗口切分的评测集。

难点：真正的视频推理有显存、时延和模型访问成本；可以先用公开示例做少量案例，并把研究问题收窄成评测/分析，不必大规模训练。

## 一个可落地的最小项目：Persistent State Agent Benchmark

### 环境

用 Python 写 2D 网格环境：房间、桌子、盒子、颜色方块、可开关门。每个动作返回程序化状态和文本/简图观测；加入规则，例如物体一次只能放一处、关门会阻止移动、被遮挡物仍在原处。

### 任务集

从简单到困难分层：

1. 单步：“把红块放入左盒”。
2. 多步依赖：“开门→取钥匙→开柜→放物品”。
3. 遮挡/离开再返回：“先把蓝块放桌下，离开房间，再回来取它”。
4. 规则改变：“警报响后门锁定，先解除警报才能离开”。
5. 失败恢复：“抓取失败后重新观察、更新状态，再继续”。

测试集要有组合泛化：训练/调试只用一部分对象名称、房间布局和任务模板，测试留出新组合；避免 Agent 仅记住固定模板。

### 基线

- B0：纯 ReAct/工具调用，不维护显式持久状态；
- B1：结构化 JSON 状态，但每轮不做程序不变量验证；
- B2：结构化状态 + 确定性规则引擎；
- B3：B2 + 状态不变量检查与失败恢复；
- Ablation：去掉历史记录、实体 ID、验证器、失败观测中的某一项。

### 指标

| 指标 | 计算/含义 |
|---|---|
| Task Success | 最终状态满足任务目标的比例 |
| State Accuracy | Agent 内部状态与模拟器 ground truth 的实体/关系匹配程度 |
| Recovery Success | 注入一次执行失败后仍完成任务的比例 |
| Invalid Action Rate | 规则不允许或目标不存在的动作数 / 总动作数 |
| Calls / Tokens / Latency | 每个成功任务成本与时延 |
| Generalization Gap | 未见对象/布局组合上的成功率下降 |

要预先定义任务成功、无效动作和状态正确；不要跑完后再挑最有利的指标。

## 研究流程（8 周样例，可随课程/导师调整）

| 周 | 交付物 |
|---|---|
| 1 | 读论文、画模块图；复现一个玩具 world transition；建立文献表 |
| 2 | 固定任务定义、状态 schema、成功条件；写 10–20 个 sanity tests |
| 3 | 做 B0/B1 两条基线；确保随机种子和日志可追踪 |
| 4 | 加入规则执行器与状态验证器；编写失败/遮挡场景 |
| 5 | 扩充任务到足以统计；先跑小规模 pilot，检查指标是否有区分度 |
| 6 | 做对照与消融；保存原始轨迹、预测状态、错误案例 |
| 7 | 重跑关键实验；人工审核评估器误判；写局限性 |
| 8 | 形成短论文/组会报告：动机、方法、实验、误差分析、复现说明 |

这是建议节奏，不是发表保证。遇到结果为负也有价值：负结果可揭示显式状态在哪些任务无帮助，或维护状态的开销超过收益。

## 实验工程规范

每次实验记录：

```text
commit / 环境版本 / 模型与提示版本
任务集版本 / 场景难度 / 随机种子
基线定义 / 参数 / 运行成本
逐步输入-动作-观察-内部状态日志
最终状态与评估结果 / 失败案例
```

至少跑多个 seed 或多组任务实例；明确报告平均值和不确定性。自动指标最好辅以人工抽检。遇到失败要按类别统计（规划错、状态丢失、工具失败、环境规则 bug、评估器错），不要只展示成功案例。

## 读论文 + 读代码的两周入门计划

**第 1–3 天**：读论文摘要、引言、§3.1、Fig. 2；不用一开始抠每个引用，先能复述状态、Agent、代码、proxy、video model 的分工。

**第 4–6 天**：读 §3.2–3.3，自己画出文本与 proxy 两种条件；列出游戏数据和实拍数据构造差异。

**第 7–9 天**：读 §4–5，把所有数字/结果写成表，并标注哪些是作者报告、哪些是定性、有哪些限制。

**第 10–12 天**：在 GitHub 依次读 `INFERENCE.md`、`config.py`、`duv.py`、`cache.py`、`engine.py`，不必立即下载几十 GB 权重。

**第 13–14 天**：完成一个最小状态 Agent 环境和一页实验设计，与导师讨论范围、baseline、数据合规和算力。

## 可以直接拿去和导师讨论的问题

- 这个项目更想研究“世界状态如何维护”，还是“视频模型如何听从状态条件”？
- 目前最有价值的 gap 是 proxy 自动生成、长时身份、失败恢复、还是可量化 benchmark？
- 组里有什么现成环境、GPU、视频模型和标注资源？
- 先做纯程序化环境的可靠性实验，是否能作为低成本第一阶段？
- 评价时用哪些可自动验证的 ground truth，怎样控制变量？
- 如果论文复现中闭源游戏 proxy 工具不可得，课题边界如何重新定义？

## 给你的建议

你对 Agent 可靠性、安全与 AI 系统感兴趣的话，我建议**从“显式状态 + 执行器 + 验证/恢复”的低成本 benchmark 起步**，把 CWM 当作问题动机和系统分解参考；暂时不要承诺完整复现其视频模型训练。

第一份成果应该是可运行环境、明确的任务集、可靠的基线、能解释的失败分类；等导师确认 GPU/视频模型资源后，再考虑把 proxy-to-video 接进来。

**一句话研究原则：** 先做能测量的正确性，再追求漂亮的生成结果。
